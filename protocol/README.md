# Browser handoff v1

The JSON Schema describes message shape. `app/bridge_protocol.py` additionally enforces UTF-8, duplicate-key rejection, exact fields, numeric finiteness, URL policy and a 65,536-byte serialized-message limit. Both checks matter; JSON Schema alone does not establish source safety.

`requestId` is a lowercase random UUIDv4 (`crypto.randomUUID()`). `offerMedia` requires payload fields `url`, `title`, `referer`, `currentTime` and `subtitles`. Strings are non-null; unknown title/referer use `""`, unknown time uses 0, unknown subtitle language uses `"und"`. Subtitles contain exactly `url`, `label`, `language`. Missing, inaccessible or unsupported desired subtitles must be reported rather than silently discarded. Maximum 16 tracks; URLs 16,000 characters, title 200, labels 100, language 35, position 0–86,400 finite seconds. Only HTTPS on port 443 is accepted. Control characters, surrogates, URL credentials and local URL forms are rejected.

`getCapabilities` uses an empty payload. Native replies echo requestId with types `capabilities`, `accepted` or `failed`; failed payloads carry stable `code` and safe `message`. A framing/JSON failure may have null requestId. `accepted` acknowledges staging and app launch only, never media or TV readiness. The browser must not pause its player on this event.

Inbox files are `~/Library/Application Support/VideoBridge/Inbox/<requestId>.json`. They contain the flat validated envelope plus host-generated `createdAt` (Unix epoch seconds). Each file is a 0600 single-link regular file in a 0700 directory owned by the user. Stored total remains <=65,536 bytes. The app verifies these invariants, rejects future/older-than-60-second requests, checks token equals requestId, consumes once, and revalidates the payload before offering playback. At most 32 files may be pending. Before adding a new request, the native host removes only expired, schema-valid, owned canonical request files under the inbox lock. Symlinks, hardlinks, malformed records, foreign files and unexpired requests are preserved. Duplicate outstanding IDs with identical payload are idempotent; changed payload or expired duplicate is rejected. Consumed requests are not retained in a browsing-history log.

The only launch URL is `videobridge://request/<requestId>`; URLs/captions never enter the launch command. Chrome/Firefox native-host manifests allow only installed extension identities. The host checks browser-supplied launch arguments; these are not a defense against malicious programs already running as the same macOS user. Page events are untrusted and must never be blindly forwarded by extension background code.

Direct and nested remote media access still requires the remote-source broker's DNS, redirect and response policy. Lexical URL validation is insufficient. No cookies, arbitrary headers, filesystem paths, scripts or commands are accepted. Safari uses the same payload contract but its native extension transport remains a separate implementation.

Stage host registration with `python3 scripts/install_native_host.py --app-path /path/to/VideoBridge.app`. This writes only task-owned staging files. Review first; `--install` explicitly writes per-user manifests. Optional `--chrome-extension-id` must be the exact installed ID; Firefox's fixed ID is `videobridge@local.app`. An existing differing installation is refused rather than silently replaced. Do not commit staged configuration or personal installation paths.
